# SKYSHIELD review notes

Reviewed from two perspectives: game design and radar/IAMD education.

## Main diagnosis

The original version was coherent, but it asked a new player to understand the model before they could enjoy the game. The language used terms such as architecture, effectors, C2, saturation, resilience and evidence confidence before explaining what those ideas mean in play. The result felt more like a briefing interface than a playable learning activity.

## Game-design review

The MVP now needs a stronger player loop:

1. What is coming?
2. What must I protect?
3. What can I buy?
4. Where should I place it?
5. Why did the result happen?
6. What would I change next time?

Changes made:

- Reframed the start screen around a simple chain: see, understand, decide, act, absorb and keep going.
- Added an OCSA Coach panel that gives contextual tips while the player is building.
- Added a Mission Brief panel that lists protected sites, incoming threat mix and win condition.
- Replaced unclear resource shorthand such as `b`, `w` and `i` with budget, people and network.
- Reworded the scenario cards around player challenge and lesson.
- Reworked the debrief metrics so they explain themselves.
- Changed the replay explanation so non-specialists can read the animation.

## Radar/IAMD education review

The model should teach that IAMD is a chain, not a forcefield. That has been made more explicit throughout the text.

Changes made:

- Sensors now explain warning rather than implying protection.
- Classification is described as understanding the track, not just detecting it.
- C2 is explained as the function that turns tracks into decisions.
- Surface defence, counter-drone and electronic warfare are described by threat fit.
- Resilience is framed as reducing consequence when interception fails.
- Sustainment is framed as staying effective through later waves.
- Debrief rules now explain causal failure in plain English.
- Advice-card language now avoids overclaiming about real-world protection.

## Remaining recommended improvements

These would make the game more fun without making it less accurate:

- Add a scoring screen with three stars: protected value, efficiency and evidence confidence.
- Add scenario-specific objectives, for example: “keep Northport Energy below 3 damage”.
- Add short sound cues for detection, classification, engagement and impact.
- Add a visible wave timeline so players can anticipate repeated salvos.
- Add after-action “try this” suggestions, such as “move a local sensor to South-East Hub”.
- Add one tutorial scenario where the first placement is guided.
